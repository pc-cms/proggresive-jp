# Дилер, пит, администратор и Linux kiosk

## Дилер

На обычном экране только суммы, названия, данные стола и боксы; настройки открываются явно. Используется оформление опубликованного Progressive; локальный финансовый движок удалён из исполняемого экрана.

| Состояние | Клавиша | Действие |
|---|---|---|
| До раунда | 1–7 | Выбрать/убрать бокс |
| До раунда | Enter / NumpadEnter | Подтвердить ставки; одно начисление |
| Подтверждён | Повторный Enter | Ничего не начисляет |
| Подтверждён | 0 | Завершить, фонды не сбрасываются |
| Без участников | 0 | Подтвердить пустой раунд и завершить; одна игра, ноль ставок |
| Подтверждён | NumPad * | Начать заявление |
| Ввод выигрыша | Бокс, Enter; tier 1–5, Enter; тип 1/2, Enter; ещё Enter | Последний Enter явно отправляет заявление |
| Тип выплаты | 1 / 2 | First five / seven cards |
| Незавершённый ввод | Esc / Backspace | Отменить ввод, не отменять деньги |
| Служебный режим | F2 | Mapping клавиши заявления |
| Служебный режим | F4 | Progressive ↔ настоящий Baccarat MAX; открытый раунд сохраняется |

Подтверждённые владельцем коды: 1 Flush, 2 Full House, 3 Four of a Kind, 4 Straight Flush, 5 Royal Flush. F4 подтверждён последним запросом. `*` и коды комбинаций подтверждены владельцем; F2 открывает служебные настройки. Mapping `claim` настраивается через F2 (physical code, например `NumpadMultiply`/`F8`).

Для 1–2 дополнительный пароль по умолчанию не нужен. Для 3–5 вводятся личная учётная запись уполномоченного сотрудника и скрытый пароль. Система проверяет account и права, не подтверждает фактическую карточную комбинацию вместо менеджера. Неверный пароль не меняет деньги. После approval объявление на всех подключённых столах; `0` завершает выигравший раунд. Другие раунды сохраняются.

При потере связи не принимать новые джекпотные ставки; дождаться authoritative reconnect. Не вводить новое финансовое намерение вместо запроса с неизвестным исходом. Терминал проверяет сохранённый pending command ID. Если заявка pending/disputed, приём новых ставок казино остановлен до решения.

## Администратор/пит

`/admin`: персональный вход, общие фонды, столы, pending/disputed, devices и last_seen, report JSON/CSV. Таблица устройств показывает last_seen, а не обещает физический статус ламп; соединение свежим считается по heartbeat.

Регистрация стола не финансирует фонд снова. `pair_create` выдаёт одноразовый 10-minute код; ввести на мини-PC вместе с уникальным именем. Credentials устройства остаются в защищённом kiosk profile; никогда не экспортировать профиль публично. Замена: `device_revoke` с причиной, затем новый pairing. Действия журналируются.

Доступные команды и параметры приведены в API.md. Administrative command form — явный JSON editor для server-validated операций, не прямое редактирование balances. Использовать reason/reference, проверять результат. Credentials CMS, выданные `principal_create`, сохранить безопасно; не показывать оператору. Пароли при создании пользователей передаются только HTTPS и очищаются из формы, не журналируются.

`approve` upper-tier: администратор. При policy pit_admin — сначала отдельный pit account, затем admin; pit/admin не один principal. `paid` только после реального вручения денег с receipt/reference. `reject` требует причину. Спорные заявки остаются для разбора, не «переводятся» на новый стартовый фонд. Удалённые confirm/close/reverse проходят тот же движок.

Изменение информационных minimum/maximum не влияет на Progressive stake. Config update меняет будущие условия, а adjustment — текущий остаток с отдельной причиной.

## Linux kiosk (X11)

Предлагаемая проверяемая основа: Debian/Ubuntu X11 session, Chromium, `numlockx`, `x11-xserver-utils`, `libnss3-tools`. Для Wayland нужен отдельный OS-specific запуск, здесь он не испытан. Создать ограниченного kiosk user, выдать CA trust, назначить HTTPS URL в пользовательском session environment (`PROGRESSIVE_URL`). Поместить исходники/скрипт по пути из desktop entry либо исправить **локальную** копию entry под installation path.

1. Установить названные пакеты через доверенный apt репозиторий целевого Linux.
2. `mkdir -p ~/.config/autostart`; скопировать `scripts/premier-kiosk.desktop` туда.
3. Перед запуском desktop entry экспортировать PROGRESSIVE_URL, например через файл session environment, поддерживаемый выбранным desktop. Не полагаться на интерактивный `.bashrc` для графической сессии.
4. `scripts/kiosk.sh` включает Num Lock при старте и после падения браузера, отключает DPMS/screensaver, перезапускает Chromium через 2 секунды.
5. Настроить auto-login только выделенного kiosk user средствами выбранного display manager. Проверить после reboot отдельно на мини-PC.
6. Отключить desktop shortcuts, лишние USB устройства и доступ к shell согласно политике площадки. Один persistent Chromium profile; второй активный оператор блокируется серверной lease.

Браузер читает `event.code` (`Numpad1`, включая key=End при выключенном Num Lock), suppresses repeat и не перехватывает input/password поля. Num Lock включается при запуске, restart и X11-watchdog каждые две секунды. Реакция конкретного desktop/keyboard требует hardware acceptance. Случайное выключение Num Lock не меняет назначение игровых physical codes. Пароль в input получает обычный ввод ОС, не игровые команды.

Проверить реальный NumPad, фокус, режим пароля, Num Lock после reboot, monitor FullHD и power recovery. Физическое оборудование в облаке не проверялось.

## Постоянная страница конкретного стола

В админке после регистрации стола отображаются постоянный table_id, полный kiosk URL и кнопка выдачи кода привязки. Формат адреса: `https://<сервер>:<порт>/table/<table_id>`. Указать именно этот адрес в PROGRESSIVE_URL на мини-PC. Переименование, лимиты и перезапуск не меняют ID. Регистрация/страница не создают отдельных фондов.

Первый запуск страницы: ввести одноразовый код **этого** стола и уникальное имя устройства. Код другого стола отклоняется без расходования. Credentials хранятся в kiosk profile отдельно для каждого table_id. Если в браузере осталась привязка другого стола, игровой ввод блокируется и открывается pairing нужного стола. Корневая страница `/` сохранена для совместимости; после успешного определения своего стола она меняет адрес на постоянный `/table/<table_id>`.

ID в URL выбирает экран; управление требует device authentication и операторской lease. Неизвестный ID возвращает 404. Authenticated terminal requests посылают X-Premier-Table; сервер проверяет соответствие device/table до state, lease, commands и stream.

## Baccarat MAX

История дорог хранится на сервере отдельно по table_id. На kiosk отображаются только подтверждённые сервером результаты. Это история Baccarat, не денежный журнал Progressive. 1 Player, 2 Banker, 3 Tie, 4 Player Pair, 5 Banker Pair, 6 Super6, 7 Dragon7, 8 Panda8, 9 BigTiger, + SmallTiger; 0 новая shoe с подтверждением, Decimal/Delete/Backspace отмена. K открывает управление, S настройки, D демо. F4 возвращает Progressive. Ввод изолирован от команд Poker. Сервер задаёт название/лимиты стола; локальные настройки не меняют их. Если на старом столе modes содержит только progressive, администратор включает baccarat через table_update; новые столы поддерживают оба режима.

Выбор winning boxes: после * нажать один или несколько номеров 1–7, повторное нажатие снимает выбор, затем Enter → комбинация → тип → Enter → окончательное Enter. Для другой комбинации выбрать другие боксы отдельным заявлением. На одном боксе оплачивается только старшая комбинация.

В /admin регистрация различает Progressive Poker и Baccarat MAX. Лимиты каждого стола меняются через table_update; прошлые руки Baccarat сохраняют свои версии лимитов. Кассовое принятие/расчёт Baccarat ставок не реализовано этим монитором результатов.
